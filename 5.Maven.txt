💡 WHAT IS MAVEN & WHAT IS IT USED FOR?
 ---------------------------------------------------------------------------------------
 • **What it is:** A build automation and **project management tool** primarily used for Java.(Its a fremwork were we can change what we want if needed)
 • **What it does:** It standardizes how software is built, manages external libraries (dependencies), 
   compiles code, and packages projects into deployable files.

----Think of Maven as an online delivery courier service for your programming project.----
Instead of going out to different stores on the internet to find every piece of code your app needs (like payment tools or security libraries),
you write down a simple list of what you want.
The Order Form: You write what you need in a file called pom.xml.
The Courier: Maven reads that list, goes out to the internet, picks up all the correct parts, and delivers them straight to your project folder.
The Assembly: Maven then automatically compiles your code and packages everything into a finished file ready to run.

 • 🛒 **E-Commerce Analogy:** Imagine building an online store with a shopping cart and a 
   checkout/payment system. You need security libraries, database connectors, and payment 
   gateway plugins (like Stripe). Instead of manually searching the web and downloading 
   dozens of files, **Maven automatically fetches, manages, and wires them all together** 
   based on a single configuration file.

 ⚙️ BUILDING vs. COMPILING & COMPILER vs. INTERPRETER
 ---------------------------------------------------------------------------------------
 • **Compiling:** Translating human-readable source code into machine-level binary code (0s and 1s) 
   so the computer's CPU can understand and execute it.
 • **Building:** A bigger process. Compiling is just *one step* inside a build. A full "build" 
   includes compiling code, running unit tests, packaging everything into a `.jar` or `.war` file, 
   and generating reports.

 ⚖️ **Compiler vs. Interpreter:**
    • **Compiler:** Translates the *entire* code into machine binary **all at once** before running 
      it (e.g., Java, C++). Fast execution.
    • **Interpreter:** Translates and executes code **line-by-line on the fly** while the program 
      runs (e.g., Python, JavaScript). Slower execution, but easier to test instantly.


 📜 THE `pom.xml` FILE (Project Object Model)
 ---------------------------------------------------------------------------------------
 • **What it is:** The master configuration XML file at the root of every Maven project.
 • **What it does:** It acts as the "ID card" and "shopping list" for your app. It tells Maven:
    • What your project name and version are.
    • What external tools or dependencies your e-commerce cart/payment app requires.
    • How the project should be built and packaged.

 📦 DEPENDENCIES, REPORTS, & RELEASE DISTRIBUTION
 ---------------------------------------------------------------------------------------
 • **Dependencies:** External files/libraries your project relies on (e.g., a logging tool or 
   payment SDK). Maven downloads them automatically using the `pom.xml`.
 • **Reports:** Automated documents generated by Maven showing project health, test results, 
   and code quality metrics.
 • **Release Distribution:** Packaging your final compiled e-commerce app and uploading/publishing 
   it to a server so customers can access it live.

 🏢 THE THREE MAVEN REPOSITORIES (The Storage System)
 ---------------------------------------------------------------------------------------
 1. 💻 **Local Repository:** 
    • Where it lives: A hidden folder on **your own computer** (`~/.m2/repository`).
    • What it does: Stores downloaded libraries locally so Maven doesn't have to re-download 
      them every time you build.

 2. 🏢 **Server / Remote Repository:**
    • Where it lives: Hosted privately inside **your company** (using tools like Nexus or Artifactory).
    • What it does: Stores your company's custom, private code libraries that shouldn't be public.

 3. 🌍 **Central Repository:**
    • Where it lives: Publicly on the internet (**Maven Central**).
    • What it does: A massive global warehouse containing millions of open-source libraries 
      (like Spring, Hibernate, or JUnit) that anyone can download for free.
