Real Cloud (AWS/Azure) = The Official Central Utility Office 🏢:

requires talking to massive remote servers over the internet with strict authentication tokens.

Floci Containers = Your Local Power Generator & Water Tank 🛢️:

simulate those services right on your machine (ports 4566 and 4577), letting you test 
applications offline instantly!

How It Works (Simulating Pods Locally) ----->
Instead of struggling with lightweight EKS control-plane emulators that often settle into 
a `FAILED` state locally, you can use a custom Docker network to bridge individual 
containers together (simulating multi-container pod behavior).

⚠️ Windows Git Bash Path-Translation Note:
When running Docker inside Git Bash on Windows, prefix container commands with 
`MSYS_NO_PATHCONV=1` to prevent path conversions (e.g., turning `/bin/bash` into 
`C:/Program Files/Git/usr/bin/bash`).

────────────────────────────────────────────────--------------------------------──
📦 DOCKER & CONTAINER COMMAND REFERENCE :

1️⃣ Create a Custom Docker Network:
    docker network create ubuntu-net

2️⃣ Run Multi-Container Ubuntu Setup (with path conversion disabled):
    MSYS_NO_PATHCONV=1 docker run -d --name ubuntu-container-one --network ubuntu-net ubuntu:latest /bin/bash -c "echo 'Container One Active' && sleep 3600"
    MSYS_NO_PATHCONV=1 docker run -d --name ubuntu-container-two --network ubuntu-net ubuntu:latest /bin/bash -c "echo 'Container Two Active' && sleep 3600"

3️⃣ Inspect & View Container Logs:
    docker ps                                              // List running containers
    docker logs ubuntu-container-one                       // View logs for container 1
    docker logs ubuntu-container-two                       // View logs for container 2

4️⃣ Container Lifecycle Management Commands & Flags:
    * `-q` (or `--quiet`): Outputs only unique container ID numbers (useful for batch scripting).
    * `docker stop $(docker ps -q)`: Dynamically stops all currently running containers.
    * `docker start $(docker ps -a -q)`: Starts all containers (both running and stopped).
    * `docker rm -f <container_ids>`: Forces removal of specific running/stopped containers.
