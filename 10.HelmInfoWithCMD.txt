1. CORE CONCEPTS & ARCHITECTURE
------------------------------------------------------------------------------------------------------------------------
---> HELM: The official Package Manager for Kubernetes (Written natively in Go 🐹 for seamless API integration).[cite: 1]

+----------------------------------------------------------------------------------------------------------------------+
|                                                 THE PACKAGE MANAGERS                                                 |
+----------------------------------------------------------------------------------------------------------------------+
| Ubuntu (Debian-based)                 | Amazon Linux (RPM-based)              | Kubernetes Cluster Level                     |
| 🐧 Tool: apt                          | 📦 Tool: yum / dnf                    | ☸️ Tool: helm[cite: 1]                      |
| 💻 Command: apt install nginx         | 💻 Command: sudo yum install nginx    | 🚀 Command: helm install nginx-chart[cite: 1]|
| ⚙️ Action: Installs OS package        | ⚙️ Action: Installs RPM package       | 🏗️ Action: Installs all k8s resources auto[cite: 1]|
+----------------------------------------------------------------------------------------------------------------------+

🎨 Symbolic Connection & Metaphor:
* Kubernetes Logo = ☸ (Ship's Wheel / Helm)  --> Steers, guides, and coordinates all containerized workloads in the cluster.
* Helm Logo        = ⚓ (Ship's Anchor / Helm) --> Manages, packages, and secures applications to "drop anchor" reliably.

2. CHART STRUCTURE & TEMPLATING ENGINE
------------------------------------------------------------------------------------------------------------------------
# Instead of tracking raw, unmanaged YAML files individually, Helm bundles them into a standardized Chart package.

my-app-chart/
├── Chart.yaml             # 📋 Metadata about the chart (name, appVersion, description, dependencies)
├── values.yaml            # ⚙️ Default configuration settings & variables (non-hardcoded values injected at runtime)
└── templates/             # 🛠️ Directory holding standard Kubernetes template blueprint files
    │
    ├── [ FRONTEND COMPONENTS ]
    │   ├── service.yaml       # 🌐 Frontend Service config (exposes pods internally or externally via ClusterIP/LoadBalancer)
    │   ├── configmap.yaml     # 📝 Frontend ConfigMap (stores non-sensitive environment variables & configuration properties)
    │   └── deployment.yaml    # 🚀 Frontend Deployment application (manages pod replicas, scaling, and zero-downtime rolling updates)
    │
    └── [ BACKEND COMPONENTS ]
        ├── statefulset.yaml   # 💾 Backend Database StatefulSet (manages stateful DB pods with stable network IDs & persistent storage)
        ├── secret.yaml        # 🔐 Backend Secrets (securely stores database passwords, TLS certificates, and API keys base64-encoded)
        └── service-ports.yaml # 🔌 Backend Service ports config (defines internal networking rules, cluster ports, and routing)

+----------------------------------------------------------------------------------------------------------------------+
|                                      CLEAR VALUE INJECTION & RENDERING FLOW                                          |
+----------------------------------------------------------------------------------------------------------------------+
| STEP 1: CONFIGURATION (values.yaml)         STEP 2: BLUEPRINT TEMPLATE (templates/deployment.yaml)                   |
| -----------------------------------         ------------------------------------------------------                   |
| replicaCount: 3                             apiVersion: apps/v1                                                      |
| imageName: "nginx"                          kind: Deployment                                                         |
| imageTag: "1.21.6"                          spec:                                                                    |
|                                               replicas: {{ .Values.replicaCount }}  <-- Dynamic injection (`3`)      |
|                                               template:                                                                |
|                                                 spec:                                                                  |
|                                                   containers:                                                          |
|                                                   - name: app                                                          |
|                                                     image: {{ .Values.imageName }}:{{ .Values.imageTag }}            |
|                                                                                                                      |
|                               [ HELM ENGINE COMBINES BOTH TO GENERATE PURE K8S MANIFESTS ]                           |

⚙️ PASSING CONFIGURATION DATA IN HELM ⚓
------------------------------------------------------------------------------------------------------------------------
In Helm, **Passing Configuration Data** refers to the mechanism of supplying custom values to a chart to override its default settings (`values.yaml`). 
Instead of modifying the chart's internal files directly, you pass your configuration data outward from your local environment into the chart during installation or upgrade.

🖼️ VISUAL CONCEPT: --> CONFIGURATION CONCEPT: `--set` (COMMAND LINE) VS `--values` (MANUAL FILE EDIT) ⚓
+---------------------------------------------------------+                 +---------------------------------------------------------+
| 📄 DEFAULT CHART CONFIGURATION (`values.yaml`)          |                 | ☸️ DEFAULT K8S MANIFEST BASELINE                        |
+---------------------------------------------------------+                 +---------------------------------------------------------+
| • replicaCount: 1                                       |                 | • replicaCount: 1                                       |
| • service.type: ClusterIP                               |                 | • service.type: ClusterIP                               |
| • service.port: 80                                      |                 | • service.port: 80                                      |
+---------------------------------------------------------+                 +---------------------------------------------------------+
                             │                                                                                                    │
                             ├───────────────────────────────────────────┐                                                        │
                             │                                           │                                                        │
                             ▼ (Inline Terminal Flag)                    ▼ (External Configuration File)                          │
+---------------------------------------------------------+   +---------------------------------------------------------+         │
| 💻 METHOD 1: CLI INLINE FLAG (`--set`)                  |   | 📁 METHOD 2: EXTERNAL YAML FILE (`-f`)                  |         │
+---------------------------------------------------------+   +---------------------------------------------------------+         │
| Command:                                                |   | File (`custom-values.yaml`):                            |         │
| `helm install my-web bitnami/tomcat --set ...`          |   | • replicaCount: 3                                       |         │
|                                                         |   | • service.type: LoadBalancer                            |         │
| Use Case: Quick, single-property changes typed          |   | • service.port: 8080                                    |         │
| directly in the terminal without creating extra files.  |   |                                                         |         │
|                                                         |   | Use Case: Production environments, complex deployments  |         │
|                                                         |   | with multiple properties, ports, replicas, and secrets. |         │
+---------------------------------------------------------+   +---------------------------------------------------------+         │
                             │                                           │                                                        │
                             └───────────────────────────┬───────────────┘                                                        │
                                                         │                                                                        │
                                                         ▼                                                                        │
                                      +---------------------------------------------------------------------------------+         │
                                      | ⚙️ HELM RENDERING & TEMPLATING ENGINE                                           | <───────┘
                                      +---------------------------------------------------------------------------------+
                                      | Dynamically merges the default `values.yaml` baseline with your chosen override |
                                      +---------------------------------------------------------------------------------+
                                                                                 │
                                                                                 ▼
                                      +---------------------------------------------------------------------------------+
                                      | 🚀 FINAL RENDERED KUBERNETES MANIFESTS DEPLOYED TO CLUSTER                      |
                                      +---------------------------------------------------------------------------------+
                                      | • replicaCount: 3          (🌟 Overridden via External File)                    |
                                      | • service.type: LoadBalancer (🌟 Overridden via `--set` Flag or File)           |
                                      | • service.port: 8080       (🌟 Overridden via External File)                    |
                                      +---------------------------------------------------------------------------------+

helm install my-web bitnami/tomcat --version 0.4.0 --set service.type=LoadBalancer # ⚙️ Inline override | Overrides configuration parameter on the fly
+----------------------------------------------------------------------------------------------------------------------+
|                                     INLINE OVERRIDE FLOW (--set service.type=LoadBalancer)                           |
+----------------------------------------------------------------------------------------------------------------------+
| [ values.yaml (Default) ]          -->          [ --set Flag ]           -->          [ Rendered Manifest (ClusterIP)  ]
| service.type: ClusterIP                         service.type=LoadBalancer              service.type: LoadBalancer    |
+----------------------------------------------------------------------------------------------------------------------+
